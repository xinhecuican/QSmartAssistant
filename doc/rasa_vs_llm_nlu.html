结论先说（三条，按重要性排序）

  1. rasa 原来的 40% exact 里，有 15.4 pt 是纯粹的软件 bug。 两个自研规则抽取器（底层是 Microsoft Recognizers-Text 通用中文数字/日期解析器） 把「换一首」的「一」抽成 n=1，而且会先把 DIET 已经抽对的 number 结果删掉再塞自己的。修完之后伪数字 15 → 0、伪日期 3 → 1。
  2. 改完的 rasa 意图不输 LLM，泛化到未见实体时反超。 留出集意图 100.00% vs 98.46%、exact 90.77% vs 93.85%； 探针集 exact 94.74% vs 63.16%；延迟快 5.5–9.6 倍。
  3. 上一版所有 rasa 数字都缺一个前提：随机种子。 rasa 3.6.19 的 rasa train nlu 没有 --random-seed， 而 DIET 在未配置时用 int(time.time()) 当种子。 同一份数据同一份 config 重训两次，65 条留出集上 exact 差 3 条。 本页里控了种子的对照才当因果。

为什么是软件 bug 而不是能力问题。原始实现里有两行致命代码：

# ① 把 DIET 已经抽对的 number 全删掉，再塞自己的结果
exclude_entities = [e for e in entities if e['entity'] != 'number']
message.set(ENTITIES, exclude_entities + extracted_entities, add_to_output=True)

# ② 输出零宽 / 被截断的跨度（Recognizers-Text 的中文 offset 本来就是错的）
TEXT: 换一首   → number value=1 start=1 end=1            ← 零宽
TEXT: 今天     → time   value=2026-10-10 start=0 end=1   ← 只覆盖「今」
TEXT: 明后天   → time   value=2026-10-12 start=1 end=2   ← 只覆盖「后」
TEXT: 三十     → time   value=2026-09-30 start=0 end=1   ← 只覆盖「三」

重写后改成合并不覆盖，并加三道闸：跨度不可用就丢（零宽/截断）、 量词搭配不当数值（一首|一下|一个|一点|一遍|…）、完整数词识别。

⚠ 随机种子：不钉住 random_seed 的评测都不算数

rasa 3.6.19 · rasa/utils/tensorflow/models.py：

def __init__(self, random_seed: Optional[int] = None, **kwargs):
    ...
    if random_seed is None:
        random_seed = int(time.time())      # ← 每秒都不同
    self.random_seed = random_seed
    self._set_random_seed()                 # random / numpy / tf / keras 全套

random_seed 的来源是 DIETClassifier 组件配置 （默认 None）。而 3.6.19 的 rasa train nlu 没有 --random-seed 参数，顶层 rasa train 也没有。 所以默认情况下每次训练出来的 DIET 权重都不一样。

实测（同一份 nlu.yml + 同一份 config.yml）

exact换种子 / 不钉种子都会动 2–3 条

seed 42 · 重训 90.77% (59/65) ✓一致

怎么读后面那些阶梯数字。阶梯 T2 / T2b / T2c 是在发现这个坑之前测的， 都没控种子。最直接的证据：阶梯 T2c 是 95.38%，把同一份数据重训一次就变成 100.00%。 所以「T2c 的 trend 语料把 MUSICINFO 带坏了」这个当时的结论站不住 —— 它就是种子噪声。真正可信的只有：控了种子的 A/B、以及幅度远大于噪声的结论（20 pt vs 3 pt）。

代价是把 random_seed: 42 写进 Data/rasa/config.yml 的 DIETClassifier 段，已提交。

未见实体探针：上一版的核心假设是错的

探针用一批已放进 jieba 词典、但两侧训练集都没出现过的实体造句子 （吻别/红日/光辉岁月/晴天/七里香、王菲/张国荣/李宗盛/罗大佑/邓丽君、 天津/重庆/厦门/青岛、书房×灯 …）。这样 token 边界是好的，但 没有监督信号 —— 于是能区分「瓶颈是分词」还是「瓶颈是没有先验知识」。

怎么解释这个反直觉的结果。rasa 的优势来自「标注好边界就照猫画虎」： [X](singer) 这个模式在训练集里出现过 48 次，换一个没见过的名字进同一个位置， DIET 照样标 —— 它不需要知道王菲是谁。LLM 的劣势恰恰来自它知道太多： Qwen 知道「王菲是歌手」，但在 few-shot DSL 里 s= / g= 的判别规则 学得不够稳，于是靠常识去猜，猜反了。这也解释了它 应带/实际槽位 是 19/19 全报满、却只对 12 条。

结论与建议

结论

  1. 上一版「rasa 差 53.85 pt」的结论要撤回。修正后的量级是： 抽取出错 ≈ 15.4 pt（纯 bug）→ 语料不足 ≈ 30 pt（132 → 358 条）→ 词典拼错 + 实体标注被丢 ≈ 另有一部分 → 剩下的 ~3 pt 才是真正的能力差。
  2. 在 16 类固定指令这个封闭域里，rasa 已经是合理选择：留出集意图满分、 exact 90.77%；探针集 exact 94.74%（反超 LLM 31.58 pt）；延迟快 5.5–9.6 倍；28 MB。
  3. 但这个结论有前提，必须一起说：
    • 语料 132 → 358 条是必要条件，原始语料下怎么调都到不了；
    • 语料是为这 16 个意图定制的，扩到新意图/新实体类型要重新标注；
    • 65 条留出集已被用于迭代，90.77% 偏乐观；更可信的是探针集 94.74%， 但只有 19 条，置信区间很宽；
    • 不钉 random_seed 就没有可复现性，±3 条的抖动比很多「优化」都大。
  4. LLM 的价值不在这个封闭域内的 exact，而在开集泛化：留出集 exact 略胜 3 pt， 代价是 5.5–9.6 倍延迟、145 倍体积；探针集上反而输 31.58 pt。

落地

  • 最终模型已发布到应用实际读取的路径 Data/rasa/models/default.tar.gz （Data/default_config.json 里 rasa.model 指的就是它）。
  • 原始模型保留在 Data/rasa/models/_orig_default_pretrain.tar.gz，也可从 git 取回。
  • 训练源 Data/rasa/{config.yml, data/nlu/nlu.yml, components/} 与发布的模型一一对应，已钉 random_seed: 42。
  • 中间版本模型留在 Data/rasa/models_v2/ 供复核（不在 git 里）。

还能再改什么（按性价比排序）

  1. 给 s/g 加 RegexEntityExtractor + lookup table —— 剩余 7 条错例里 4 条是它，而歌手/歌名本身就是有限集合，成本很低。
  2. 把 trend 跨度在 normalizer 里再收敛一次：把声音调大点 现在标成 t=调，应按字表收敛到含方向字的那个字/词。
  3. 补同音变体表（「客听」→「客厅」），或在训练前统一做同音纠错。
  4. 给「家」这类词定标注口径，两侧同改，否则永远是错例。
  5. 混合路线接口：rasa 的 confidence_entity / confidence_role 可以直接做阈值，低置信度整句升到 LLM。

环境坑（都是踩过的）

  1. rasa 3.6.19 只支持 Python 3.8–3.10；embedding 包要手工改 python310._pth + get-pip.py。
  2. transformers 必须钉 4.36.2（rasa 里 from transformers import TFPreTrainedModel，5.x 删掉了 TF 支持）。
  3. Agent.load() 不会把 CWD 加进 sys.path，项目内相对组件导入会失败。
  4. os.chdir(rasa_dir) 会打断相对路径参数 —— 必须先把所有路径 abspath()。
  5. rasa train nlu 既没有 --force 也没有 --random-seed； 前者删 .rasa/cache 替代，后者只能写进 config 的 DIETClassifier 段。
  6. 实体标注跨 jieba token 边界会被 静默丢弃（只发 UserWarning，样本保留、实体丢掉）。改完 nlu.yml 一定跑一遍对齐检查。
  7. dicionary_path 这类拼错不会报错，只会静默不加载 —— 改 config 后核对模型包里 有没有真的出现 components/train_*。
