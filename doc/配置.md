配置目录在`~/.config/QSmartAssistant`，插件和配置文件都在该目录下，程序目录下Data文件夹会自动复制到配置目录中

## 配置文件格式（YAML，2026-10 起）

配置文件为`Data/config.yaml`,修改配置文件之后进入build目录运行`cmake ..`会自动复制配置文件到配置目录

第一次运行可以将`Data/default_config.yaml`复制为`Data/config.yaml`

**同时支持 yaml 与 json，老 json 会自动迁移：**

1. 启动时**优先读 `config.yaml`**，存在就用它；
2. 若只有老版本 `config.json`，则读入后**立即写出 `config.yaml`**（自动迁移），此后以 yaml 为准；
3. 老 `config.json` **保留不删**（只读不写），便于对比与回滚。

```
~/.config/QSmartAssistant/Data/
├── config.yaml            # 运行期配置（真正被读的那份）
├── default_config.yaml    # 模板，承载每个选项的注释
└── config.json            # 老版本（可选），仅用于迁移读取
```

注释**内嵌在 `default_config.yaml`** 里。所用的 yaml 库（yaml-cpp）写盘时会丢弃注释，
所以程序每次保存都会按模板的键路径**重新贴回**注释——运行期 `config.yaml` 因此同样带说明。

> 编辑注意：`Data/default_config.yaml` 是**模板**，改它只影响「新生成」的运行期配置；
> 已存在的 `config.yaml` 不会被覆盖——想让改动生效要**两边都改**。
> 运行期配置是**独立副本、不是软链**：改仓库 `Data/` 不会改变 `~/.config/...` 那份。

### 路径解析（Linux / Windows 通用）

所有「路径类」选项（模型文件、词典、`netease_cloud.homeDir` 等）都走同一个解析函数，
因此**同一份配置在两端都能用**：

| 你写的值                        | 解析方式                                                              |
| ------------------------------- | --------------------------------------------------------------------- |
| `onnx_nlu/nlu_int8.onnx`        | **相对路径** → 拼到数据根 `~/.config/QSmartAssistant/Data` 下         |
| `/home/user/models`             | **绝对路径**（Linux）→ 原样使用                                       |
| `D:/models` 或 `D:\models`      | **绝对路径**（Windows）→ 原样使用（正反斜杠都行）                     |
| `~/models`                      | `~` 展开为用户主目录                                                  |
| *（留空）*                      | 数据根本身                                                            |

下面两种写法都合法且可移植：

```yaml
sherpa:
  model: sherpa-onnx-paraformer-zh-small-2024-03-09/model.int8.onnx  # 相对路径
# 或指向外部位置：
sherpa:
  model: D:/models/paraformer/model.int8.onnx                        # 绝对路径（Win）
#   model: /opt/models/paraformer/model.int8.onnx                    # 绝对路径（Linux）
```

数据根本身可用环境变量 `QSA_DATA_DIR` 覆盖（容器 / systemd 下很有用）：

```bash
QSA_DATA_DIR=/opt/qsa/data ./QSmartAssistant
```

注意：绝对路径只对**某一个**系统成立，因此那些需要「一字不改」跨平台共用的选项
（例如 `netease_cloud.homeDir`）还额外支持**自动探测**：当配置的路径不存在时
会自动去找常见位置。详见下方 `netease` 小节。

除 `QSA_DATA_DIR` 外，另有几个环境变量便于自定义部署：

| 变量             | 作用                                                              |
| ---------------- | ----------------------------------------------------------------- |
| `QSA_DATA_DIR`   | 覆盖数据根（默认 `~/.config/QSmartAssistant/Data`）               |
| `QSA_RASA_VENV`  | Rasa 虚拟环境路径（仅当 `nlu.backend = rasa` 时使用）             |
| `QSA_NODE_EXE`   | netease 插件使用的 `node` 可执行文件                              |

示例（节选）：

```yaml
wakeup:
  chunkSize: 640              # 每帧采样数（16k 单声道 PCM；640 = 40ms）
  detectSlient: 800           # 唤醒后静音多少 ms 判定一句话结束
  intentMap:                  # 唤醒词直接映射意图，跳过 VAD/ASR/NLU
    - index: 10086
      text: 开灯
      intents:
        - name: OPEN_FURNITURE
          slots:
            - name: furniture
              value: 灯
```

## onnx nlu

选项：`onnx_nlu` —— 替代 rasa DIET 的自研 NLU。
结构：`rbtl3 (BertModel) + 意图头(16 类) + 逐 token 槽位头(9 类: O + n t s g f l m c d)`，
并把 rasa 的三个规则组件用 C++ 重写（`canon_map` ≡ EntitySynonymMapper、
`trend_*` ≡ custom_trend_normalizer、`d` 的「去个+掐尾」≡ custom_time_extractor）。
推理走项目**已有的** onnxruntime（唤醒词在用），进程内、无端口。

| 选项    | 默认值                 | 含义 |
| ------- | ---------------------- | ---- |
| model   | onnx_nlu/nlu_int8.onnx | int8 量化模型（57MB）。int8 与 fp32 指标**完全一致** |
| vocab   | onnx_nlu/vocab.txt     | 词表 |
| rules   | onnx_nlu/rules.json    | 规则层（同义词映射、趋势归一化） |
| schema  | nlu_schema.json        | 意图/槽位 schema，须与训练时一致 |
| conf    | 0.5                    | 置信度阈值，低于则拒识 |
| max_len | 64                     | 最大输入 token 数 |
| threads | 0                      | ONNX 线程数，0 = 自动 |

> ⚠ `schema` 必须与训练时**逐字一致**。改 schema 后所有评测集都会失效，需重新生成。
> ⚠ `TimeNormalizer` 允许输出区间 `"a|b"`（如「明后天」），校验时别把 `|` 当脏数据。

两把验收尺子：`tools/onnxnlu_test/parity_check.py`（C++ ↔ Python 逐字对拍，须 95/95）
与 `accept_runtime.py`（parseIntent 之后的下游槽位空间对 gold）。

# rasa配置

rasa配置目录在`Data/rasa`中,[文档](https://rasa.com/docs/rasa/)

rasa NLU的目的是从文本中抽取出意图和实体，例如`[增大](trend)音量`，它的意图是`CHANGE_VOL`,其中包含`trend`实体

rasa训练命令为`rasa train nlu -c config.yml`。训练完成之后在model文件夹下会生成一个模型，如果需要替换需要更改config.yaml中的配置并重新启动。



## 流水线

流水线是rasa NLU的处理流程，大致可以分为tokenizer, featurizer,intent classifier,entity classfier。流水线配置在`Data/rasa/config.yml`中，[文档位于](https://rasa.com/docs/rasa/components)

- tokenizer: 分词，中文一般使用jieba分词
- featurizer: 词向量化
- intent classifier: 意图抽取
- entity classfier: 实体抽取

## 实体和意图

可以参照`Data/rasa/domain.yml`进行配置，其训练语料位于`Data/rasa/data/nlu`中，如果想自定义实体和意图可以在domain.yml中添加定义，然后再data/nlu中添加训练语料，然后运行训练命令训练，最后在config.yml中修改模型位置即可

# llm

llm 后端由 `Utils/LLM/LLMManager.cpp` 管理，每个后端都有一个名称，名称即 `llm.backends` 下的键名。

```yaml
llm:
  proxy: 127.0.0.1:7890        # HTTP 代理，空串表示直连
  default: deepseek-v3.2       # 默认后端名
  llamaDir: ""                 # llama.cpp 运行库目录（本地 GGUF 后端）
  backends:                    # 键名即「模型名」
    deepseek-v3.2:
      modelName: deepseek-ai/DeepSeek-V3.2   # 请求体里的 model 字段
      key: sk-xxx
      maxTokens: 160000
      api_base: https://api.siliconflow.cn/v1/chat/completions
    # 本地 llama.cpp 后端
    local-qwen:
      type: llamacpp
      model: Qwen3.5-2B-Q4_K_M.gguf   # GGUF 文件（Data/ 下）
      gpuLayers: 0                    # 卸载到 GPU 的层数，0 = 纯 CPU
```

> `llm.proxy` 同样被 chat 插件使用；完全离线运行时置为 `""`。

# netease cloud

选项：`netease_cloud` —— 网易云音乐插件。

> **懒登录**：插件加载（程序启动）时**不启动 node 服务、不登录**，只解析配置。
> 只有首次真正用到网易云（说出命中音乐意图的指令）时才拉起 node 并登录。
> 因此不用网易云的用户零开销，也不会在启动阶段撞上网易的风控（`code -462`）。

| 选项              | 默认值 | 含义 |
| ----------------- | ------ | ---- |
| phone             | xxx    | 手机号。`email` 为空时走 `/login/cellphone` 登录 |
| password          | xxx    | 密码 |
| email             | ""     | 邮箱登录走 `/login`；非空时用该通道，且**没有短信兜底** |
| captchaTimeoutSec | 300    | 短信验证码有效期（秒） |
| apiMode           | node   | `node`（本地 NeteaseCloudMusicApi）或 `official` |
| cookie            | ""     | 登录态缓存；有效时跳过登录 |
| volumeStep        | 10     | 每次调节音量的步长 |
| homeDir           | ""     | NeteaseCloudMusicApi 安装目录。**留空即自动探测** |
| port              | 34793  | 本地 API 端口 |
| nodeExe           | ""     | `node` 可执行文件路径。**留空即自动探测**（先查 PATH，再查 Program Files\nodejs、nvm、scoop、winget 等） |

`homeDir` 跨平台通用：

- **留空（推荐）** → 自动探测。插件按顺序尝试：`$QSA_NETEASE_HOME`、
  `~/.config/QSmartAssistant/lib/NeteaseCloudMusicApi`、仓库相对路径
  `lib/NeteaseCloudMusicApi`（以及 `Plugins/neteasemusic/NeteaseCloudMusicApi`）、
  数据根相对路径 `lib/NeteaseCloudMusicApi`。第一个含 `app.js` 的目录胜出。
- **绝对路径** → 直接使用，但 Linux 路径在 Windows 上解析不了（反之亦然）。
  想让一份配置两端通用，建议留空。
- 若都没找到：插件打印警告并跳过 node 后端，助手其余功能不受影响。

`netease_cloud.official` 在 `apiMode == "official"` 时使用：

| 选项         | 含义 |
| ------------ | ---- |
| appId        | 应用 ID |
| privateKey   | RSA 私钥（PEM） |
| clientSecret | 客户端密钥 |
| baseUrl      | 接口基址 |
| deviceId     | 设备 ID |
| clientIp     | 客户端 IP |
| timeoutMs    | 请求超时 |
| qrLogin      | 是否用扫码登录 |

> ⚠ 网易风控：邮箱密码登录返回 code `501`（凭据不匹配），手机号密码登录常返回
> `-462`（人机验证，`randomCNIP` / 伪造 `realIP` 都绕不过）。
> **短信验证码是唯一可靠的自动登录路径。**
> ⚠ `privateKey` / `clientSecret` 是密钥，`default_config.yaml` 里只留空串——
> 请只写进自己的 `~/.config/QSmartAssistant/Data/config.yaml`，不要提交到仓库。
